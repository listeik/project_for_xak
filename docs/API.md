# REST API

Запуск: `python -m uvicorn app.main:app --reload --port 8000`.
Интерактивная схема: `/docs`, OpenAPI: `/openapi.json`.
Расчёты выполняются только сервером; план каждого запроса независим. Сервер
не сохраняет пользовательские планы и не разделяет их между сеансами.

| Метод и путь | Результат |
| --- | --- |
| `GET /api/v1/health` | Статус, версия исходных данных и модели |
| `GET /api/v1/case` | Авторитетные CSV/YAML параметры и единицы |
| `GET /api/v1/default-plan` | Исходное гибридное предложение, не доказанный оптимум |
| `POST /api/v1/calculate` | Полный расчёт `calculate_plan` |
| `POST /api/v1/optimize` | `{plan, result, optimization}` |
| `POST /api/v1/export?format=csv\|xlsx\|json` | Скачиваемый результат того же расчёта |

## План запроса

Все POST принимают один и тот же JSON. Пример можно получить через
`GET /api/v1/default-plan`. Обязателен `yearly_orders` со всеми годами
2035–2040; каждый год содержит все пять числовых полей `A`, `B`, `C`, `D`, `E`.
Строки, логические значения, отрицательные числа, NaN/Infinity, неизвестные
поля и неизвестные каналы отклоняются HTTP 422. Нулевой заказ разрешён.

```json
{
  "plan_id": "my-hybrid-plan",
  "scenario": "BASE",
  "yearly_orders": {
    "2035": {"A": 110, "B": 0, "C": 0, "D": 0, "E": 0},
    "2036": {"A": 150, "B": 0, "C": 0, "D": 0, "E": 0},
    "2037": {"A": 190, "B": 0, "C": 10, "D": 0, "E": 0},
    "2038": {"A": 190, "B": 0, "C": 0, "D": 80, "E": 0},
    "2039": {"A": 190, "B": 0, "C": 30, "D": 110, "E": 0},
    "2040": {"A": 190, "B": 0, "C": 90, "D": 115, "E": 0}
  },
  "yearly_reservations": null,
  "investments": {
    "zbo_year": 2036,
    "option_c_year": 2035,
    "exercise_c_year": 2035,
    "isru_funding_year": 2037
  },
  "initial_inventory_t": 15,
  "discount_rate": 0.08,
  "c_lead_months": 24,
  "d_lead_months": 2,
  "demand_factor": 1,
  "price_factor": 1
}
```

`yearly_reservations` — необязательный словарь год → канал → бронь в т/год.
Он может содержать только отдельные годы/каналы: отсутствующие брони ядро
вычисляет по заказу и доступной доле года. Явный ноль остаётся нулём.
`investments` по умолчанию содержит четыре `null` (не инвестировать).
Годы решения — целые 2035–2040 или `null`. Ранний ZBO, позднее ISRU и
неправильная последовательность C возвращаются как нарушения модели,
а не ошибки структуры JSON.

Сценарий: `BASE` или `MANDATORY_STRESS`. C lead time: 18–24 месяца; D: 1–2.
Discount rate: 0–1, то есть 0–100% годовых. Для защиты численной арифметики
массы и брони ограничены 10⁹ т, исследовательские множители — диапазоном
0–1000. Это технические границы ввода, не физические пределы кейса.
Если множители спроса/цены отличаются от 1, результат помечается
`assumptions.research_factors_active=true`: это исследование чувствительности.

## Результат и ошибки

Успешный расчёт возвращает HTTP 200 даже при `feasible=false`. Он содержит
`annual_balances`, `kpi_summary`, `graph_data`, `violations`,
`violation_details`, `inventory_trace`, `source_schedule`, `startup_stock`,
`financial_breakdown`, `assumptions`, `units` и версии данных/модели.
Имена полей — snake_case и совпадают с расчётным ядром. Денежные величины —
млн условных единиц в постоянных ценах 2035, доли сервиса — 0–1.

`violations` — коды; `violation_details` раскрывает год, источник, предел,
фактическое значение и сообщение. Отсутствие формальных нарушений в STRESS
само по себе не доказывает нулевой дефицит: проверяйте `total_shortage`.

Структурная ошибка — HTTP 422: `message` и стандартный массив `detail`
с `loc`, `type`, `msg`, `input`. Некорректный JSON также возвращает 422.
Оптимизатор при невозможности решения возвращает HTTP 422:
`detail.code="OPTIMIZATION_INFEASIBLE"`, `detail.message`, `detail.details`.
Прочие внутренние ошибки возвращают 500 с понятным сообщением без traceback.

Оптимизация меняет годовые заказы при фиксированных инвестициях и остальных
допущениях входного плана. Полученный план повторно проверяется тем же ядром.
Объект `optimization` раскрывает статус, метод и область гарантии оптимума.

## Выгрузки и браузер

CSV с UTF-8 BOM содержит годовой баланс со всеми колонками; вложенные
контракты сериализуются в JSON-ячейки. В каждой из шести строк также указаны
`scenario_id`, `plan_id`, `input_version`, `model_version`, `fuel_unit`,
`money_unit`, `assumptions_json`, `plan_json`, поэтому сценарий, единицы,
допущения и решения сохраняются вместе с численными результатами. Перед
опасными префиксами формул в строковых CSV-ячейках добавляется апостроф;
исходное название плана доступно без изменения внутри `plan_json`.
XLSX содержит восемь листов: `annual_balances`, `financial`, `source_schedule`,
`inventory`, `violations`, `assumptions`, `plan`, `metadata`. Последний лист
указывает сценарий, идентификатор плана, единицы, версии данных/модели и
исполнимость плана.
JSON соответствует `schemas/export.schema.json` и дополнительно включает
исходный `plan` и полный `result`. `risk_register=[]` явно означает, что реестр
FMEA не заполнен и вероятностная модель риска не выполнялась.
CSV — таблица для анализа, полная воспроизводимая выгрузка — JSON.

Ответы выгрузки включают `Content-Disposition`. Имя файла формируется из
сценария и хеша идентификатора плана; пользовательский текст в заголовок
не попадает. Для повторного открытия фронтенд сохраняет/загружает JSON плана
локально; сохранять его на сервере не требуется.

`ALLOWED_ORIGINS` — разделённые запятыми полные origin-адреса фронтенда.
По умолчанию разрешены `http://localhost:5173,http://localhost:8080`.
Передача cookies отключена; `Content-Disposition` доступен JavaScript.
На хостинге укажите точный HTTPS-origin статического фронтенда.
