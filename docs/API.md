# REST API

## Уточнения экспертов и обоснование выбора — версия 2.2

[Обоснование решения](decision_brief.md), [экспертные уточнения](EXPERT_NOTES.md), [методика реакции](RESPONSE.md). Основная реакция использует только обеспеченную до шока мощность; новая мощность — отдельное условное исследование. Для C разделены подготовка 18–24 месяца и доставка после ввода (допущение 4 месяца). Добавлены общий земной сбой A/B/C/E и рекомендация по измеримым последствиям, стоимости и остаточному риску. Эта методика заменяет трактовки доступности новых контрактов и сроков C в описании 2.1.

Новые поля `PlanRequest`:

| Поле | Значение по умолчанию | Смысл |
|---|---|---|
| `response_capacity_policy` | `booked_only` | Реакция в пределах исходной брони. `conditional_market` разрешает исследовать новую мощность |
| `new_capacity_fraction` | `1.0` | Доля оставшейся технической мощности, доступная для новых договоров в условном режиме; от 0 до 1 |
| `c_delivery_lead_months` | `4.0` | Срок текущей поставки C, от 0 до 24 месяцев; допущение команды |
| `c_lead_months` | `24` | Существующее поле: подготовка C после исполнения опциона, от 18 до 24 месяцев |

`/analytics/stress` возвращает `adaptation` в пределах брони и отдельную `conditional_adaptation`, со своими ошибками проверки. В полном отчёте `comparisons.decision_case` содержит шесть кандидатов, их планы и проверенные последствия двух отдельных шоков, условную рекомендацию и её правило. `evidence_register` раскрывает основания и границы утверждений; `c_delivery_sensitivity` показывает последствия изменения срока доставки C. `decision_comparison.rows` содержит до пяти рассчитанных вариантов. `report_version` — `1.2`, `model_version` — `2.2-evidence`.

Отчёт не гарантирует нахождение решения за лимит решателя. Неподтверждённые варианты явно обозначены и не включаются в рекомендацию. Время полного расчёта зависит от мощности сервера; результат содержит статус каждой проверки.

## Реакция после шока (2.1)

`POST /api/v1/adapt` принимает PlanRequest, включает MANDATORY_STRESS и возвращает `{plan, result, actions, optimization}`. Профиль — BASE, пользовательский шок отключается; множители запроса сохраняются. `additional_orders` содержит дозаказы, `contract_lock` — исходные обязательства с политикой `preserve_commitments_allow_timed_topups`. Частичное восстановление — успешный расчёт с `full_recovery=false` и остаточными нарушениями. Неподтверждённое решение — HTTP 422 `RESPONSE_NOT_VERIFIED`; занятый аналитический слот — 429.

`POST /api/v1/analytics/stress` дополнительно возвращает исходный BASE и неизменный STRESS; для стандартного сравнения сбрасывает множители до 1. Полный `/analytics/report` и конкурсные JSON/CSV включают `decision_comparison`, `stress_impact.adaptation`, `service_tradeoff`, стоимость подготовленного BASE и STRESS. Обычный экспорт сохраняет дозаказы в плане и отдельные окна в `source_schedule`. Методика: [RESPONSE.md](RESPONSE.md).

Запуск: `python -m uvicorn app.main:app --reload --port 8000`.
Интерактивная схема: `/docs`, OpenAPI: `/openapi.json`.
Расчёты выполняются только сервером; план каждого запроса независим. Сервер
не сохраняет пользовательские планы и не разделяет их между сеансами.

## Конфигурация и аналитика 2.0

`research_config` расширяет стандартный набор дополнительными источниками и непрерывными годами 2041–2045. Схемы: `app/schemas/research.py`. Суммарно допускается до 12 источников и 11 лет; обязательные A–E и 2035–2040 сохраняются. Для каждого будущего года передаются четыре значения спроса, для нового источника — мощность, цена, бронь, TOP, сроки, доступность и обоснование. Новые источники трактуются как покупная услуга без отдельного инвестиционного CAPEX. Нужны явные `assumptions`, `future_capex_limit_mln` и `future_policy`. Базовые пороги, цены и резерв продолжаются по выбранному явному правилу; обязательные шоки после 2040 не продлеваются.

`research_shock` задаёт ID `TEAM_*`, описание, годы, множитель спроса и воздействия по каналам (`price_factor`, `delivery_factor`, `capacity_factor`, `delay_months`). В BASE применяется отдельно. Совместно с MANDATORY_STRESS требует `multiply_independent_effects`; обоснование независимости остаётся ответственностью автора сценария. Задержка означает пропуск начала окна поставки без наверстывания, а не моделирование очереди с переносом топлива.

`contract_lock` хранит исходные заказы, инвестиции, явную бронь, начальный запас и lead time с годом реакции. Контракты с первой датой заказа до шока фиксируются полностью. Структурно несовместимый контекст отклоняется HTTP 422; попытка изменить зафиксированный заказ возвращается как `SUNK_CONTRACT_CHANGED_*`. LP использует равные нижнюю/верхнюю границы этих заказов.

`reserve_target_days` — целевой физический резерв 45–90 дней, не ослабляющий минимум организатора. `cost_per_served_ton` — все недисконтированные затраты / фактическая выдача; `discounted_cost_per_served_ton` — NPV / та же выдача. При нулевой выдаче оба значения `null`.

Сравнение шаблонов явно возвращается к стандартному профилю/множителям для сопоставимости. Полный отчёт сохраняет также первоначальный `plan` и его `selected_result`, хеш плана, входов, версию и timestamp. Тяжёлый аналитический запрос допускается один на процесс; конкурентный получает HTTP 429 с понятным сообщением. Обычный расчёт и оптимизация остаются независимыми.

## План запроса

Все POST принимают один и тот же JSON. Пример можно получить через
`GET /api/v1/default-plan`. Обязателен `yearly_orders` со всеми годами
2035–2040; каждый год содержит все пять числовых полей `A`, `B`, `C`, `D`, `E`.
Строки, логические значения, отрицательные числа, NaN/Infinity, неизвестные
поля и неизвестные каналы отклоняются HTTP 422. Нулевой заказ разрешён.

```json
{
  "plan_id": "my-hybrid-plan",
  "scenario": "BASE",
  "yearly_orders": {
    "2035": {"A": 110, "B": 0, "C": 0, "D": 0, "E": 0},
    "2036": {"A": 150, "B": 0, "C": 0, "D": 0, "E": 0},
    "2037": {"A": 190, "B": 0, "C": 10, "D": 0, "E": 0},
    "2038": {"A": 190, "B": 0, "C": 0, "D": 80, "E": 0},
    "2039": {"A": 190, "B": 0, "C": 30, "D": 110, "E": 0},
    "2040": {"A": 190, "B": 0, "C": 90, "D": 115, "E": 0}
  },
  "yearly_reservations": null,
  "investments": {
    "zbo_year": 2036,
    "option_c_year": 2035,
    "exercise_c_year": 2035,
    "isru_funding_year": 2037
  },
  "initial_inventory_t": 15,
  "discount_rate": 0.08,
  "c_lead_months": 24,
  "d_lead_months": 2,
  "demand_factor": 1,
  "price_factor": 1
}
```

`yearly_reservations` — необязательный словарь год → канал → бронь в т/год.
Он может содержать только отдельные годы/каналы: отсутствующие брони ядро
вычисляет по заказу и доступной доле года. Явный ноль остаётся нулём.
`investments` по умолчанию содержит четыре `null` (не инвестировать).
Годы решения — целые 2035–2040 или `null`. Ранний ZBO, позднее ISRU и
неправильная последовательность C возвращаются как нарушения модели,
а не ошибки структуры JSON.

Сценарий: `BASE` или `MANDATORY_STRESS`. C lead time: 18–24 месяца; D: 1–2.
Discount rate: 0–1, то есть 0–100% годовых. Для защиты численной арифметики
массы и брони ограничены 10⁹ т, исследовательские множители — диапазоном
0–1000. Это технические границы ввода, не физические пределы кейса.
Если множители спроса/цены отличаются от 1, результат помечается
`assumptions.research_factors_active=true`: это исследование чувствительности.

## Результат и ошибки

Успешный расчёт возвращает HTTP 200 даже при `feasible=false`. Он содержит
`annual_balances`, `kpi_summary`, `graph_data`, `violations`,
`violation_details`, `inventory_trace`, `source_schedule`, `startup_stock`,
`financial_breakdown`, `assumptions`, `units` и версии данных/модели.
Имена полей — snake_case и совпадают с расчётным ядром. Денежные величины —
млн условных единиц в постоянных ценах 2035, доли сервиса — 0–1.

`violations` — коды; `violation_details` раскрывает год, источник, предел,
фактическое значение и сообщение. Отсутствие формальных нарушений в STRESS
само по себе не доказывает нулевой дефицит: проверяйте `total_shortage`.

Структурная ошибка — HTTP 422: `message` и стандартный массив `detail`
с `loc`, `type`, `msg`, `input`. Некорректный JSON также возвращает 422.
Оптимизатор при невозможности решения возвращает HTTP 422:
`detail.code="OPTIMIZATION_INFEASIBLE"`, `detail.message`, `detail.details`.
Прочие внутренние ошибки возвращают 500 с понятным сообщением без traceback.

Оптимизация меняет годовые заказы при фиксированных инвестициях и остальных
допущениях входного плана. Полученный план повторно проверяется тем же ядром.
Объект `optimization` раскрывает статус, метод и область гарантии оптимума.

## Выгрузки и браузер

CSV с UTF-8 BOM содержит годовой баланс со всеми колонками; вложенные
контракты сериализуются в JSON-ячейки. В каждой строке выбранного горизонта также указаны
`scenario_id`, `plan_id`, `input_version`, `model_version`, `fuel_unit`,
`money_unit`, `assumptions_json`, `plan_json`, поэтому сценарий, единицы,
допущения и решения сохраняются вместе с численными результатами. Перед
опасными префиксами формул в строковых CSV-ячейках добавляется апостроф;
исходное название плана доступно без изменения внутри `plan_json`.
XLSX содержит девять листов: `annual_balances`, `financial`, `source_schedule`,
`inventory`, `violations`, `warnings`, `assumptions`, `plan`, `metadata`. Последний лист
указывает сценарий, идентификатор плана, единицы, версии данных/модели и
исполнимость плана.
JSON соответствует `schemas/export.schema.json` и дополнительно включает
исходный `plan` и полный `result`. `risk_register=[]` в обычной выгрузке означает,
что риск-реестр не включён в эту операцию. Рассчитанный детерминированный реестр
доступен через `/analytics/risks` и конкурсный экспорт. Вероятностная модель
риска не выполняется.
CSV — таблица для анализа, полная воспроизводимая выгрузка — JSON.

Ответы выгрузки включают `Content-Disposition`. Имя файла формируется из
сценария и хеша идентификатора плана; пользовательский текст в заголовок
не попадает. Для повторного открытия фронтенд сохраняет/загружает JSON плана
локально; сохранять его на сервере не требуется.

`ALLOWED_ORIGINS` — разделённые запятыми полные origin-адреса фронтенда.
По умолчанию разрешены `http://localhost:5173,http://localhost:8080`.
Передача cookies отключена; `Content-Disposition` доступен JavaScript.
На хостинге укажите точный HTTPS-origin статического фронтенда.
